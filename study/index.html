E0 · 45 min · read, do not open SQL yet

Requirements first, then the architecture

Meridian has 520 branches and five currencies. Reports disagree because they all query the core banking database. Card decisions take days. Fraud shows up on the statement. The platform’s job is one governed answer, in minutes, scoped to the person asking.

Prerequisites

The clone. No Snowflake login. No Docker. Read 00_architecture/ARCHITECTURE_PROCESS.md in order: requirements, context, conceptual model, one grain, container and flow, then one ADR with the option you refused.

Files

  • 00_architecture/DESIGN_DOC.md
  • 00_architecture/ARCHITECTURE_PROCESS.md
  • 00_architecture/diagrams/01_context.mmd through 04_data_flow.mmd
  • 00_architecture/adr/0001 … 0011-multitenancy-patterns.md and adr/README.md
  • 07_data_modelling/BUS_MATRIX.md
Run

There is no command. Open the design doc and say the grain of fct_transactions out loud before any worksheet.

Expected result

You can restate the numeric NFRs: hot facts ≤ 15 minutes p95, dimensions ready by 06:00 local, zero error-test failures before publish, reconciliation inside $0.01 after a 2-minute fair cutoff, deny by default, mart RPO ≤ 1 day, mart RTO ≤ 4 hours, resource monitor suspends at 90%.

Failure modes you must be able to name
  • Extract dies after COPY and before the watermark moves. Next run reloads the window. Raw appends. Staging dedupes.
  • A source delete is invisible unless cdc.deleted_records has the tombstone.
  • A weekend with no FX rate is forward-filled and flagged.
  • A model under the AUC gate is stored as REJECTED. Marts keep the previous good scores.
  • CREATE OR REPLACE drops a row policy. The dbt post-hook puts it back. Until governance is installed, the hook warns and grants nothing.
DESIGN_DOC.md§1–§4

Requirements and the arithmetic

  1. §1 The problem is disagreeing reports, slow card decisions, and late fraud. The goal is one answer per question, scoped to the person.
  2. F1–F7 Twenty operational tables move without changing the banking app. Amounts exist in local currency and USD. Customer history is true on the date asked. Dimensions are shared. Cards, English questions, and identifier search are in scope.
  3. NFR table Each target has a measurement and a consequence. Freshness is a source-freshness check. Correctness is a dbt gate. Access is a row policy plus ACCESS_HISTORY.
  4. §4 volumes Course seed is 200k customers, about 300k accounts, 5M transactions. The production sketch is 2M transactions a day.
  5. Storage arithmetic 2M × 250 bytes ÷ 5× compression is about 100 MB/day. Storage is cheap. Compute is the bill.
  6. Micro-batch arithmetic 288 runs × about 150 seconds is about 12 XS-hours a day, about 360 credits a month at the stated $3 assumption. Reference tables do not belong on that clock.
00_architecture/adr/0001–0011

One decision per file

  1. 0001 Watermark CDC on updated_at, with trigger-maintained deletes. Log-based CDC is the upgrade when freshness must fall below about a minute.
  2. 0002 Raw is append-only VARIANT so a new source column does not break COPY. Typing happens in dbt.
  3. 0003 The presentation layer is a Kimball star. Data Vault is recorded as extra cost for one source system.
  4. 0004 dbt transforms. Airflow orchestrates. Dynamic Tables and Tasks are the native alternative, demonstrated and then suspended.
  5. 0005 Model scores land in MERIDIAN_RAW.ML. They are not written back to Postgres.
  6. 0006 Row access keys on the Snowflake user. Security owns entitlements. The app does not invent a second filter.
  7. 0007 Iceberg waits until a second engine needs the tables.
  8. 0008 Terraform owns platform objects. dbt owns data objects and their grants. Security SQL owns policies.
  9. 0009 Identifier search is a serving table plus Search Optimization. A second search engine waits until the thing being searched is a document.
  10. 0010 Contracts enforce dim_branch, dim_customer, and fct_transactions. Private intermediates stay uncontracted. Raw keeps a warning-level key sentinel.
adr/0011-multitenancy-patterns.md1–64

Shared tables, policy isolation

  1. 1–15 One bank, many countries, one star. A country_code, a customer id, or a UUID names the tenant. It does not authorize the reader. Primary and foreign keys are informational. NOT NULL can require the column. Presence is still not permission.
  2. 17–29 The decision is shared database, shared schema, shared tables, one dbt project, one contract. Isolation is a row access policy on CURRENT_USER() and APP_USER. RAP_COUNTRY_SCOPE takes country_code. The Hong Kong user sees HK only. A user with the same role and no entitlement sees zero rows. That role is MERIDIAN_COUNTRY_OFFICER, shared by the officer, the staff member, and the unentitled user, and it is not granted MERIDIAN_RAW. Branch personas stay on the branch and customer policies. One table accepts one row policy, so the country policy is not bolted onto those tables.
  3. 31–38 The options table: shared tables plus a policy (this bank), schema per tenant, database per tenant, and a UUID or country predicate typed into the query. The last one is never the control, because any client can drop the predicate.
  4. 40–46 A UUID identifies a row. The policy identifies the caller, including for a query that never mentions country_code.
  5. 48–64 One backfill and one semantic view. A bad transform hits every country, which is why 11_mart_integrity_and_quarantine.sql exists. Noisy neighbors are a warehouse question (labs 03 and 09). Adding a country is an entitlement row. Revisit when a country needs its own key, its own failover, or a guarantee that no shared table exists. Even then, keep the policy inside that database.

Exercise

On paper, draw the context box with no product names inside it. Write the grain sentence for transactions. Write the CDC choice and the upgrade that would replace it.

Interview defense

“Design a near-real-time feed from an operational database into Snowflake.” Walk left to right. The built cadence is a five-minute micro-batch aimed at a 15-minute p95. Deletes are logged. A lag window covers long transactions. Raw is append-only. Staging dedupes. Marts merge. Control tables show each batch. Streaming and Snowpipe are the upgrade in ADR 0001 when seconds matter. ADR 0011 keeps one shared star and isolates countries with a row policy. A separate database is the revisit when a country needs its own key or its own failover.

01_ddl_core_schema.sqlheader and schemas

3NF source, on purpose

  1. Schemas ref holds currencies, countries, channels, products, FX, merchants, sales, offers. core holds branches, employees, customers, accounts, holders, transactions, loans, and later cards. cdc holds delete tombstones.
  2. Conventions Surrogate ids, created_at / updated_at, and natural business keys. The warehouse will throw these keys away as the grain and replace them with surrogates.
  3. Traps The transaction cursor column is left without its ideal index so performance lab 01 can show a sequential scan. Fix it there, live.
  4. Why this shape OLTP wants one account and one insert, row storage, indexes, and ACID. An analyst scan of 5M rows on this database competes with tellers. The warehouse is the other shape: columnar, pruned, denormalised.
04_cdc_triggers.sql1–11 and trigger bodies

Two guarantees the watermark needs

  1. updated_at Every change bumps the cursor. A bulk fix with triggers disabled is invisible. Daily reconciliation is the safety net. ADR 0001 names log-based CDC as the repair.
  2. Deletes A hard delete writes cdc.deleted_records. The extractor loads that table. Staging removes the key. A watermark query cannot see a row that is already gone.
  3. Replica identity The script prepares logical replication so a later Debezium or Openflow connector can read the same tables. Staging does not have to change shape.

A moving bank, then SQL by hand

  2. 06 lessons Each commented block is one idea: filters, joins, aggregates, windows. Run one block, read the result, then the next. The window block is where ROW_NUMBER, RANK, and DENSE_RANK show their tie behaviour.

Design the star before you build it

Kimball’s four steps: choose the business process, declare the grain, choose the dimensions, choose the facts. The bus matrix is that choice written as a grid.

Prerequisites

07_data_modelling/BUS_MATRIX.md, 07_data_modelling/star_schema.mmd, ADR 0003. The SQL that will implement this is 04_dbt_meridian_dw/models/marts/core/, read now and run in E6.

Run

Read the matrix row by row. Say each grain sentence at the bottom of BUS_MATRIX.md.

Expected result

You can place every fact: transactions are one row per movement at latest status; month-end balance is one row per account per month; loan and card applications are accumulating snapshots; branch daily performance is an aggregate. BUS_MATRIX.mdtable and grain list

Processes, grains, conformed dimensions

  1. Rows Each business process becomes one fact. Transactions, balances, loans, card authorizations, card applications, offers, FX, branch-day.
  2. Columns Date, customer, account, branch, product, channel, currency, transaction type, employee, merchant, sale event. An X means the fact uses that conformed dimension.
  3. PIT Customer and account on a transaction use the surrogate that was valid at transaction_ts. A June premium segment must not rewrite March.
  4. Bridge bridge_account_customer carries joint holders and a weighting factor so a sum is not double-counted.
  5. Junk dim_transaction_type is type crossed with status, a small dimension so the fact stays numeric.
  6. Unknown member Missing lookups become -1. The fact still loads. The gap stays visible.
fact grain · lab 04 laterpredicate

A fan-out is a grain error

  1. Wrong join Customer id alone matches every SCD2 version. Rows out explode. Amounts multiply.
  2. Right join valid_from <= transaction_ts < valid_to. The multiplier returns to one.
  3. Proof 06_performance_lab/04_join_explosion_scd2.sql and the dbt test assert_scd2_no_overlapping_versions.sql. Overlapping versions make the predicate ambiguous, so the test forbids them.
Failure modes

Declaring “one row per customer” and then storing every transaction on that row. Mixing a stock (balance) into a flow fact. Using today’s segment on last year’s transactions. Forgetting the bridge weight on joint accounts.

Exercise

Pick a March transaction for a customer who becomes premium in June. Name which surrogate key is correct, and which join predicate selects it.

Interview defense

Three fact types live here: a transaction fact for each movement, a periodic snapshot for month-end balances, and an accumulating snapshot for an application that gathers dates as it moves. Conformed dimensions are built once and reused. History is type 2 with a half-open interval.

dbt cannot fetch Postgres. This job reads a window, writes Parquet, PUTs it to an internal stage, and COPY INTO an append-only VARIANT table. The watermark moves only after success. A replay of an old window does not move it.

P0 green. E1 database complete. E3 scripts 01–03 applied. .env filled from .env.example with your account and key path. Never commit .env.

Expected output

Failure modes
  • Missing .env or key: connector error before any COPY. Fix the env. Do not reset the watermark.
  • Failure after COPY and before watermark merge: status FAILED in LOAD_LOG if the log write succeeds. Next run re-reads the same window. Staging dedupes.
  • --since without --until, or without --tables, or combined with --loop: the program exits with a sentence.
  • Timezone-naive bounds are rejected. Use Z or an explicit offset.
